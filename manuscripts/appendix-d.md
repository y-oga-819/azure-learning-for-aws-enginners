# 付録D 学習用サブスクリプションの課金事故防止ガイド

学習で Azure を触るときに一番怖いのは、**消し忘れによる課金事故**です。本付録は、無料枠の考え方・消し忘れ対策・予算アラート運用を 1 か所にまとめた「事故を起こさないためのチェックリスト」です。予算アラートの設計は第 5 章、Azure Bastion など有料リソースの扱いは第 4 章と対応しています。

<div class="note">
<span class="note-title">注意:アラートは「止める」仕組みではありません</span>

予算アラートは、金額を超えても**リソースを自動で止めてはくれません**。あくまで「気づく」ための通知です。通知が来たら、自分で不要なリソースを消します。「止まるはず」と思い込むのが最大の事故のもとです。

</div>

## D-1 無料枠の考え方

Azure の無料枠は、大きく 3 種類に分かれます。金額・期間・対象サービスは変わりやすいため、契約前に必ず公式ドキュメントで最新を確認してください。

| 種類 | 内容 | 注意点 |
|---|---|---|
| 初回クレジット | 新規アカウントに一定期間の無料クレジット | 期間を過ぎると従量課金へ切り替わる<!-- 要検証: 公式Doc確認 — 金額と期間 --> |
| 12 か月無料 | 対象サービスが 1 年間、一定量まで無料 | 対象・上限量は変わる。対象外サービスは初日から課金<!-- 要検証: 公式Doc確認 — 対象サービスと上限 --> |
| 常に無料 | 一部サービスが恒常的に一定量まで無料 | 「常に無料」でも上限を超えれば課金<!-- 要検証: 公式Doc確認 — 対象サービスと上限 --> |

<p class="caption">図D-1 Azure 無料枠の 3 種類</p>

<div class="note">
<span class="note-title">注意:無料クレジットの期間終了に気をつける</span>

初回クレジットは、期間終了と同時に**自動で従量課金へ切り替わる**設定になっていることがあります。「クレジットがあるから大丈夫」と置きっぱなしにしたリソースが、期間終了の翌日から課金対象になる——という事故が起きやすいポイントです。クレジットの残額と期限は、後述の予算アラートとあわせて把握しておきます。

</div>

## D-2 「無料の器」と「有料の中身」を見分ける

本書で作った土台には、**器は無料・中身が有料**というものが多くあります。この線引きを覚えておくと、何を消せばよいかが即座に分かります。

| 分類 | 具体例 | 課金 |
|---|---|---|
| 器(無料) | 管理グループ、サブスクリプション、リソースグループ | 器自体は無料。中に有料リソースを置くと課金が始まる |
| 統制・ID(無料) | Entra ID グループ、RBAC、Azure Policy | 機能自体は無料(動的グループ/PIM はライセンス要) |
| ネットワークの器(無料) | VNet、サブネット、NSG | 器は無料 |
| 監視(有料) | Log Analytics ワークスペース | 取り込み量・保持期間で課金。全部・無期限を避ける |
| 有料の中身 | Azure Bastion、仮想マシン、パブリック IP | 置いておくだけで課金が続く。使ったら消す |

## D-3 消し忘れ対策のチェックリスト

学習セッションのたびに、次を習慣にします。とくに第 4 章の疎通確認で使う Azure Bastion・仮想マシン・パブリック IP は、消し忘れの筆頭です。

- [ ] **作ったら消す**を基本にする。1 回の学習で作ったものは、その日のうちに片づける
- [ ] 有料リソース(Bastion / VM / パブリック IP)は疎通確認が済んだら**即削除**する
- [ ] まとめて消したいものは**リソースグループごと削除**する(CFn スタック削除の感覚)
- [ ] セッション終了時に、残っている有料リソースがないか一覧で確認する
- [ ] 予算アラートの通知が来ていないかを確認する

リソースグループ単位でまとめて消す例です。

```bash
# リソースグループごと削除(中身もまとめて消える)
az group delete --name rg-foundation-dev --yes --no-wait

# 有料リソースが残っていないかを横断的に確認する
az resource list --query "[?type=='Microsoft.Network/bastionHosts' || type=='Microsoft.Compute/virtualMachines' || type=='Microsoft.Network/publicIPAddresses'].{name:name, type:type, rg:resourceGroup}" --output table
```

## D-4 予算アラートの運用

第 5 章で設定した予算アラートを、学習用に運用する型です。サブスクリプションごとに月額の予算を置き、しきい値でメール通知します。

| 設定項目 | 推奨(学習用) | 備考 |
|---|---|---|
| 予算の単位 | サブスクリプションごと | dev/prod を分けて把握する |
| 期間 | 月次 | 毎月リセットされる |
| しきい値 | 50% / 80% / 100% で通知 | 早めに気づけるよう複数段で設定 |
| 通知先 | 自分のメール | 通知が来たら不要リソースを消す |
| 金額 | 無理のない少額から | 学習規模に合わせて低めに置く |

<p class="caption">図D-4 学習用の予算アラート設定</p>

Azure CLI で dev サブスクリプションに月額予算を作る例です。金額・通知先は自分の環境に合わせて変更します。

```bash
az consumption budget create \
  --budget-name budget-foundation-dev \
  --amount 3000 \
  --time-grain Monthly \
  --category Cost
```

<div class="column">

予算アラートのメールが届いたら、犯人捜しの前に「いま何が動いているか」を一覧で確認するのが近道です。多くの場合、原因は Azure Bastion や仮想マシンの消し忘れ、あるいは Log Analytics の取り込み量です。図D-3 のコマンドで有料リソースを洗い出し、不要なものからリソースグループごと消していきます。「通知 → 一覧 → 削除」を 1 セットの動作として体に入れておくと、学習中の課金は十分小さく保てます。

</div>
