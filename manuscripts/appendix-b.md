# 付録B 用語対訳集

AWS 経験者がとくに**取り違えやすい・語感で誤解しやすい** Azure 用語を集め、意味と「AWS のどの感覚で読むと事故るか」を短くまとめました。続巻でも共通して参照する用語です。対訳と表記の正は `shared/glossary.md`、本付録はその「読み解きノート」にあたります。

## B-1 まず押さえる 5 語

Azure の階層と ID を理解する土台になる 5 語です。ここを取り違えると、以降の設計判断がすべてずれます。

| 用語 | 意味 | AWS 経験者が誤解しやすい点 |
|---|---|---|
| テナント | Entra ID のディレクトリ。組織の ID の入れ物で、すべての最上位 | AWS アカウントの「上」に ID 層がある感覚。IAM はアカウント内、Entra ID はテナントにある |
| 管理グループ | サブスクリプションを束ねる統制の階層。ポリシー・RBAC を継承させる | AWS の OU に近いが、ルート管理グループ直下にも継承が効く点に注意 |
| サブスクリプション | 課金とポリシーの境界。リソースが実際に置かれる器の 1 つ上 | 「AWS アカウント」に一番近いが、ID を持たない(ID はテナント側) |
| リソースグループ | ライフサイクルを共にするリソースの入れ物。まとめて削除できる | AWS に対応物がない。タグでも CFn スタックでもない中間物。**必須の器**であって任意ではない |
| リージョンペア | 東日本↔西日本のように、あらかじめ決められた対リージョン | AWS のように任意リージョン間で組む前提と違い、**ペアが固定**。DR 設計に影響する |

## B-2 ID・権限まわり

| 用語 | 意味 | AWS 経験者が誤解しやすい点 |
|---|---|---|
| Entra ID | テナント全体の ID ディレクトリ(旧称は使いません) | IAM の置き換えではなく、IAM の「ユーザー・グループ」部分がテナントに引っ越したイメージ |
| セキュリティグループ(Entra ID) | 権限をまとめて付与するための ID グループ | **ネットワークのセキュリティグループ(SG)とは無関係**。同じ「セキュリティグループ」でも別物 |
| Azure RBAC | ロール × スコープ × プリンシパルで認可を決める仕組み | IAM ポリシー(JSON)を書く発想ではなく、組み込みロールを選んでスコープに割り当てる |
| スコープ | ロールを効かせる範囲(管理グループ/サブスクリプション/RG/リソース) | 上位で割り当てると下位へ継承する。IAM の Resource 指定より階層的 |
| マネージド ID | Azure リソースに付く、キー不要の ID | インスタンスプロファイルに近いが、対応サービスが広い。「キーを持たせない」既定手段 |
| PIM | 特権を必要なときだけ一時昇格させる仕組み | 常時付与を避ける文化の中心。P2 ライセンス前提で、学習段階では未使用 |

## B-3 ネットワークまわり

| 用語 | 意味 | AWS 経験者が誤解しやすい点 |
|---|---|---|
| 仮想ネットワーク(VNet) | Azure のプライベートネットワーク空間 | VPC 相当だが、**パブリック/プライベートサブネットの区別がない** |
| NSG | サブネットや NIC に付ける L4 フィルタ | SG と NACL の両方の役割を 1 つで担う。サブネットにも NIC にも付く |
| サービスタグ | `Internet` や `VirtualNetwork` などの、 IP の代わりに使える名前 | セキュリティグループの参照(SG を参照する書き方)に近い発想 |
| Private Endpoint | PaaS をプライベート IP で閉域接続する仕組み | VPC エンドポイント相当。PaaS が既定でパブリックなため重要度が高い |
| 可用性ゾーン | リージョン内の物理的に分離したデータセンター群 | AWS の AZ に相当。ただし全リージョンで 3 ゾーン提供とは限らない<!-- 要検証: 公式Doc確認 — 各リージョンのゾーン提供状況 --> |
| リージョンペア | DR 用にあらかじめ組まれた対リージョン | ペアが固定である点が AWS と大きく違う |

## B-4 統制・監視・IaC まわり

| 用語 | 意味 | AWS 経験者が誤解しやすい点 |
|---|---|---|
| Azure Policy | 監査・強制(拒否)・修復を行うガバナンスの仕組み | SCP(上限)と Config(可視化)を 1 つで兼ねる。段階導入(監査→拒否)が定石 |
| イニシアティブ | 複数のポリシーをまとめた束(ポリシーセット) | 個々のルールをまとめて割り当てる単位 |
| 除外(Exemption) | ポリシーの対象から一時的に外す仕組み | 恒久的な穴ではなく、理由・期限を添えて登録する |
| Log Analytics ワークスペース | ログの集約・クエリの基盤 | CloudWatch Logs 相当だが、「1 つに集約」する文化が強い |
| アクティビティログ | サブスクリプションの操作証跡 | CloudTrail 相当。診断設定でワークスペースへ送る |
| KQL | ログ検索のクエリ言語 | Logs Insights と役割は同じだが構文が違う。パイプで絞り込む |
| Bicep | ARM テンプレートの人に優しい DSL | CFn/CDK 相当。状態は ARM が持ち、外部の状態ファイルを持たない |
| ARM(Azure Resource Manager) | すべてのデプロイが通る共通基盤 | ポータルも CLI も Bicep も、最終的にここを通る |

<div class="column">
<span class="column-title">コラム:同じ言葉で別物、に注意</span>

Azure と AWS のあいだで、**同じ言葉が別の対象を指す**ことがあります。とくに「セキュリティグループ」は要注意で、Entra ID の**セキュリティグループ(ID をまとめる箱)**と、ネットワークの **NSG(通信を絞るフィルタ)**は、まったくの別物です。本書では前者を「セキュリティグループ」、後者を「NSG」と呼び分けています。用語で迷ったら、対象が「人・ID の話か」「通信の話か」を先に見分けると取り違えを防げます。

</div>
