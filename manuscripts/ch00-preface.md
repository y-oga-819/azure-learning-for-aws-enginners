# まえがき

本書『AWS経験者のためのAzure実践入門【共通基礎編】』を手に取っていただき、ありがとうございます。

本書は、AWS(Amazon Web Services)で一通りの環境構築を経験したエンジニアが、Azure の土台——ID・ガバナンス・ネットワーク・監視・IaC——をハンズオン形式で身につけるための本です。単なるサービスの対応表ではなく、「なぜ Azure はこう設計されているのか」を AWS との対比を通じて理解し、最終的に **ミニランディングゾーン** と呼べる再現可能な土台を組み上げることをゴールとします。

## 本書の対象読者

- AWS でアカウント設計・IAM・VPC・監視の構築を経験したことがある方
- これから Azure を業務や個人プロジェクトで使う必要がある方
- 「Azure のサービス名は聞いたことがあるが、AWS の知識をどうマッピングすればよいか分からない」と感じている方

逆に、クラウドそのものが初めての方には向きません。本書は AWS の知識を「消す」のではなく「活かす」ことを前提に、随所で AWS との差分だけを説明していくためです。

## 本書のゴール

読み終えたとき、次の状態ができあがっています。アプリケーションはまだ 1 つも載っていませんが、**載せる前に決めるべきことを決め切った**状態です。

- 管理グループ配下に dev / prod のサブスクリプション(または読み替えとしてリソースグループ)がある
- 必須タグ・許可リージョンなどの基本ポリシーが効いている
- 管理者 / 開発者 / 閲覧者のグループと RBAC(Role-Based Access Control、ロールベースのアクセス制御)が設計されている
- Hub-Spoke を見据えたアドレス設計の仮想ネットワークが dev / prod に 1 つずつある
- すべてのログが 1 つの Log Analytics ワークスペースへ集まり、予算アラートが設定されている
- 以上のうち仮想ネットワークとリソースグループが Bicep でコード化され、削除しても再構築できる

## 本書の進め方

各章は、次の 5 部構成で統一しています。毎章同じ順序で進むため、どの章からでも「いま何を読んでいるか」を見失いません。

| # | 節 | 読みどころ |
|---|---|---|
| 1 | 概要 | Azure における位置づけと設計思想 |
| 2 | AWSとの対応と相違 | 対応するサービス、似ている点、決定的に違う点 |
| 3 | 全体構成に組み込む | 前章までの構成に、この章の要素をどう足すか |
| 4 | 設計のポイント | セキュリティ・統制・コストのチェックリスト |
| 5 | 構築手順 | 手を動かす最小手順 |

<p class="caption">図0-1 各章の 5 部構成</p>

節の見出しには、この定型ラベルに続けて章ごとの主題を添えています。目次を眺めるだけでも、各章が何を扱うのかが分かるようにしました。なお、総仕上げの第 7 章だけは新しいリソースを作らないため、3 番目の節を「全体構成を確認する」に振り替えています。

章は積み上げ式です。第 1 章の器の上に第 2 章の ID が乗り、その上にガバナンス・ネットワーク・監視が重なります。**原則として順番に読み進めてください**。前章までに作ったものが、次章の前提になります。

## 手を動かすための前提

ハンズオンは、次の環境を前提にしています。

- **Azure のサブスクリプション**:個人の学習用で構いません。本書は dev / prod の 2 つを使う構成を主軸としますが、1 つしか用意できない場合は付録E の読み替えで最後まで進められます。
- **Azure CLI**:操作は原則として `az` コマンドで示し、必要に応じてポータルの手順を併記します。コマンドはコピーして使えるようにしてあります。
- **課金**:本書で作るリソースの多くは無料ですが、一部(Azure Bastion や仮想マシンなど)は置いておくだけで課金が続きます。第 5 章で予算アラートを設定し、付録D に消し忘れ対策をまとめました。**手を動かす前に付録D へ目を通しておくことをおすすめします**。

## 表記について
