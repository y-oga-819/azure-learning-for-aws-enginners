# 付録E リソースグループ分離への読み替え表

本書は dev/prod の分離方式に **サブスクリプション分離** を主軸として採用しています(第 1 章)。境界が最も強く、実務のランディングゾーンに近いためです。しかし、無料アカウントや個人の従量課金では、サブスクリプションを自由に増やせないことがあります。

そうした読者のために、本文の手順を **リソースグループ分離** へ読み替えるための対応表をまとめました。1 つのサブスクリプションの中に、dev/prod をリソースグループで分けて進める方式です。以降の各章も、この読み替えで最後まで通せます。

<div class="note">
<span class="note-title">注意:読み替えると弱くなる境界がある</span>

リソースグループ分離は手軽ですが、**サブスクリプション分離ほど境界は強くありません**。とくに「課金の分離」と「サブスクリプション単位のポリシー/予算」は、そのままの粒度では再現できません。学習には十分ですが、本番の分離設計では原則サブスクリプション分離を選びます。この弱まりを理解したうえで読み替えてください。

</div>

## E-1 分離の基本方針

| 観点 | サブスクリプション分離(本文) | リソースグループ分離(読み替え) |
|---|---|---|
| 分離の器 | dev/prod を別サブスクリプションに | 1 サブスクリプション内で dev/prod を別リソースグループに |
| 環境の表し方 | サブスクリプション名(`sub-foundation-dev` 等) | リソースグループ名(`rg-foundation-dev` 等) |
| ポリシーの割り当て先 | 管理グループ / 各サブスクリプション | 管理グループ / サブスクリプション / **リソースグループ**へ寄せる |
| RBAC の割り当て先 | サブスクリプション スコープ | **リソースグループ スコープ** |
| 予算の単位 | サブスクリプションごと | サブスクリプション全体 + タグ(`env`)別の把握で代替 |

## E-2 章別の読み替え

各章のハンズオンを、リソースグループ分離で進める場合の読み替えです。リソース名は `shared/state.md` の実際の名前に合わせています。名前(`rg-foundation-dev` など)は両方式で共通です。**違うのは「何をどのスコープに割り当てるか」**だけです。

| 章 | サブスクリプション分離(本文) | リソースグループ分離(読み替え) |
|---|---|---|
| 第1章 | dev/prod を別サブスクリプション(`sub-foundation-dev` / `-prod`)として用意し、各々に `rg-foundation-dev` / `-prod` を作成 | 1 サブスクリプション内に `rg-foundation-dev` / `rg-foundation-prod` を作成。命名・タグ・リージョンの規則はそのまま |
| 第2章 | `grp-foundation-developers` などに、`sub-foundation-dev`= 共同作成者 / `sub-foundation-prod`= 閲覧者を割り当て | 同じグループに、**`rg-foundation-dev` スコープ**= 共同作成者 / **`rg-foundation-prod` スコープ**= 閲覧者を割り当て。「dev は緩く、prod は厳しく」はスコープを RG に替えて表現 |
| 第3章 | 共通ポリシー(必須タグ・許可リージョン)は管理グループへ、prod 限定(パブリック IP 禁止)は `sub-foundation-prod` へ | 共通ポリシーは管理グループ/サブスクリプションへ、prod 限定は **`rg-foundation-prod` スコープ**へ割り当て。段階導入(監査→拒否)は同じ |
| 第4章 | `vnet-foundation-dev`(`10.10.0.0/16`)を dev サブスクリプションに、`-prod`(`10.20.0.0/16`)を prod サブスクリプションに構築 | 同じ VNet を、それぞれ `rg-foundation-dev` / `rg-foundation-prod` の中に構築。CIDR 設計・サブネット・NSG はそのまま |
| 第5章 | 監視用 `rg-monitor-foundation` と `log-foundation` を prod サブスクリプションに 1 つ作成。dev/prod のアクティビティログを集約 | 同じサブスクリプション内に `rg-monitor-foundation` を作り `log-foundation` を 1 つ配置。**診断設定はサブスクリプション単位のアクティビティログを 1 つ送る**形になる点に注意(下記参照) |
| 第6章 | dev の VNet 一式を Bicep 化し、削除→再構築で再現性を確認 | 同じ Bicep を、対象リソースグループを `rg-foundation-dev` にして適用。デプロイ先スコープが RG になるだけで手順は同じ |
| 第7章 | 到達状態を図7-5 と突き合わせてセルフ監査 | 「サブスクリプション」を「リソースグループ」に読み替えたうえで、同じチェックリストでセルフ監査 |

## E-3 読み替えで注意する 3 点

読み替えで境界が弱まる、または挙動が変わる箇所です。ここだけは意識しておきます。

| 論点 | 何が変わるか | 対処 |
|---|---|---|
| 課金の分離 | RG 分離では dev/prod の課金がサブスクリプションで合算される | 予算はサブスクリプション全体で置き、`env` タグでコストを分けて把握する(付録D) |
| アクティビティログ | アクティビティログはサブスクリプション単位。dev/prod で別々には出せない | 1 サブスクリプションのアクティビティログを `log-foundation` へ送る。リソースの診断ログは RG/リソース単位で分けられる |
| ポリシー/予算の粒度 | サブスクリプション単位の割り当てが、そのままの粒度では効かせられない | 環境差はリソースグループ スコープへ寄せて表現する(第3章の prod 限定ポリシーなど) |

<div class="column">
<span class="column-title">コラム:社内 DX 編はこちらが出発点</span>

続巻の**社内 DX 編**は、個人〜小規模での学習・検証を主な想定とするため、この付録E のリソースグループ分離を出発点に採用します。本書をサブスクリプション分離で通した読者も、社内 DX 編では「1 サブスクリプション + リソースグループ分離」に軸足を移す場面が出てきます。そのとき、この読み替え表がそのまま橋渡しになります。どちらの方式で学んでも、命名・タグ・ポリシー・監視の「型」は共通です——分離の器が変わるだけだと捉えてください。

</div>
